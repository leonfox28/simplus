# Bug Analysis: GHCR HEAD probe exited before image publication

## 1. Root Cause Category

- **Category**: D/E — Test coverage gap plus implicit curl assumption.
- **Specific Cause**: the workflow used `curl --request HEAD` for two registry
  manifest-existence probes. That changes the HTTP method but does not enable
  curl's HEAD response handling, so curl still expected the `Content-Length`
  body that GHCR correctly omitted and exited 18 before returning the HTTP
  status to the shell.

The GitHub Actions log is decisive evidence: all three image jobs stopped in
the first probe with `curl: (18) transfer closed with 70 bytes remaining to
read`; no build, digest staging, tag promotion, or manifest publication ran.

## 2. Why Earlier Checks Missed It

1. Static workflow and action lint validated YAML/shell syntax, not curl's
   protocol-mode semantics.
2. PR jobs intentionally never authenticate to or probe GHCR, so the correct
   no-push policy also meant this tag-only branch first ran in production.
3. Contract tests checked immutable-tag ordering and failure closure but did
   not distinguish curl's `--head` behavior from a manually selected method.

## 3. Prevention Mechanisms

| Priority | Mechanism | Specific action | Status |
| --- | --- | --- | --- |
| P0 | Runtime correctness | Replace both probes with `curl --head` while retaining explicit 200/404 classification | Done |
| P0 | Test coverage | Require exactly two `--head` probes and reject `--request HEAD` in the container workflow contract | Done |
| P1 | Documentation | Record the curl HEAD/body-transfer rule in the versioned release spec and error matrix | Done |
| P1 | Rollout discipline | Keep incomplete `v0.1.0` immutable and publish the code fix only from a new `v0.1.1` tag | Done |

## 4. Systematic Expansion

- **Similar issues**: both pre-build reuse and pre-promotion race probes used
  the same incorrect flag, so the fix and assertion cover both call sites.
- **Design improvement**: the registry response remains classified solely by
  HTTP status; no response body is parsed or required.
- **Process improvement**: tag-only network operations need semantic contract
  assertions even when PR policy correctly forbids external publication.
