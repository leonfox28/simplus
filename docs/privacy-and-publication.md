# 公开资料与隐私边界

Simplus 的代码、产品目标、架构、决策、开发进度、通用测试和脱敏兼容性结论可以公开。个人部署现场和原始实验材料不属于公开项目记录。

## 公开仓库允许内容

- 产品范围、非目标和架构不变量；
- 公开执行计划、完成状态和下一步；
- 通用开发、安装和恢复方法；
- 不关联具体个人环境的兼容性矩阵；
- 稳定错误码、通用排障顺序和安全日志边界；
- 合成 fixture、Simulator 数据和自动化测试；
- 第三方依赖的版本、许可证和来源。

## 必须保存在私有记录系统的内容

- 订阅完整 URL、原始 YAML、代理节点地址或凭据；
- 真实 LAN/VPN 拓扑、主机地址、路由器配置和本机用户名/绝对路径；
- SIM、eUICC、IMS、设备序列号、电话号码和任何可关联身份；
- AKA、SIP 鉴权、Cookie、管理员密码、私钥和 controller secret；
- 原始 HIL、逐节点结果、命令输出、服务日志、抓包、数据库和截图；
- 逐次排错时间线、个人环境恢复过程和已经退出公开产品范围的私人规划。

即使私有记录使用 Git，也不得提交仍有效的凭据或原始鉴权材料。需要保留的高敏感工件应放在仓库外的加密存储中。

## 从私有记录提炼公开结论

公开文档只回答以下问题：

1. 哪项能力实现了；
2. 证据等级是什么；
3. 哪些边界仍未验证；
4. 哪个自动化测试或稳定错误码可以防止回归。

删除运行日期、地址、节点、订阅、流量计数和个人路径。不要用“脱敏”替代必要性判断：对公开架构没有帮助的现场细节应直接不发布。

## 发布流程

1. 私有开发仓库保持 private；
2. 将需要保留的现场记录复制到独立私有记录系统并校验；
3. 在公开工作树删除原始记录，更新所有引用；
4. 运行 `make check-docs` 和工作树 secret scan；
5. 从脱敏快照创建全新的 Git 根提交，不直接把既有私有历史改成 public；
6. 对新仓库历史再次扫描，并人工检查 Actions、issues、release assets 和生成物；
7. 轮换所有曾进入聊天、日志、工作树或旧 Git 历史的有效凭据；
8. 由仓库所有者复核根 [`LICENSE`](../LICENSE)、[`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) 和最终文件清单后，才创建或切换公开远程。

`.gitignore` 只能阻止未跟踪文件被普通 `git add` 选中，不能清除已提交历史，也不能替代发布前复核。

## 自动检查范围

`make check-docs` 除链接和文档地图外，还拒绝公开 Markdown 中常见的私人痕迹：

- RFC1918 地址；
- 个人 home 绝对路径；
- URL userinfo 和常见代理分享 URI；
- `token=`、`password=` 等查询凭据；
- 与 IMSI、ICCID、IMEI、EID、IMPI、IMPU 或 MSISDN 相邻的长数字身份；
- 已知只属于当前私人实验环境的产品外标识。

公开前还应使用独立 secret scanner 同时检查工作目录和完整新历史。扫描输出必须启用 redaction，报告本身不得进入 Git。
