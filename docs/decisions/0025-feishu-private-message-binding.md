# 0025：飞书应用私聊一键绑定

- 状态：Accepted / Implemented
- 日期：2026-08-11

## 背景

现有通知渠道只支持企业微信和飞书群自定义机器人 Webhook。飞书 Webhook 需要管理员
在开发者页面手工创建并复制 credential，也不能自然表达“向完成授权的用户私聊”这一
目标。Simplus 仍只需要单向出站通知，不需要接收飞书消息、事件或远程命令。

飞书官方提供 RFC 8628 风格的一键创建应用流程：管理端生成短期验证链接，管理员确认
后返回新应用凭据和授权用户的 `open_id`。该流程由 Simplus 主动轮询，不要求公网回调。

## 决定

1. 通知页提供零表单的飞书私聊绑定入口。每次绑定只创建新应用，选择最小基础模板，
   且权限严格限于应用身份发送消息；不配置事件、回调、Webhook 或 WebSocket。
2. MVP 只接受飞书中国版租户，并把授权用户的 `open_id` 作为唯一目标。不发现、选择或
   投递群聊，也不提供入站消息或远程控制能力。
3. 授权结果先经过有界校验并发送一次私聊测试。只有测试成功后，App ID、App Secret
   和 `open_id` 才以字段独立的实例密钥标签加密并写入 core v23 的独立应用渠道表。
   短期验证链接和 device code 只存在于进程内存。
4. 同一实例最多有一个等待或测试中的绑定。进程退出、拒绝、过期、取消、非法结果、
   测试失败或持久化失败都不得形成可用渠道；公共接口只返回稳定错误码。
5. 应用渠道绑定后可编辑名称、事件、启停状态并显式测试。解绑只删除 Simplus 本地
   记录和本地凭据使用权，不停用或删除飞书侧应用，界面必须明确提示该边界。
6. 原有企业微信/飞书 Webhook 表和行为保持兼容。应用渠道通过 `deliveryMode` 与
   `targetType` 显式区分，不能借用 Webhook 密文字段承载应用 credential。

## 后果

- Simplus 无需公开 OAuth callback、入站服务或通用飞书 OpenAPI 代理；外部客户端只访问
  固定飞书注册、tenant token 和消息发送端点，并拒绝重定向、超大响应与非法结果；
- 飞书应用可能在测试或本地保存失败前已经创建，需由管理员在飞书开发者后台人工处理；
- core v23 回滚必须先执行 Down；这只移除本地应用绑定，旧 Webhook 行不受影响；
- 自动化验证全部使用合成 transport，不创建真实应用，也不发送真实消息。
