# 0028：统一 control 状态、安装初始化与持久通知

- 状态：Accepted
- 日期：2026-09-30

保留 Go、React、SQLite 和 control／agent／netd 三进程。此次重构允许破坏旧 API 和
数据库兼容性；使用独立的新数据布局，发现旧布局拒绝启动，不迁移、删除或覆盖旧数据。
control 的业务状态收敛到一个 SQLite 数据库，Agent 的硬件短信恢复数据库保持独立。
管理员创建与实例就绪在安装事务中完成，登录直接进入管理界面，删除 Bootstrap、本地
CA、首次登录硬件检查及录音目录流程。此决定取代此前这些流程与多库兼容性的要求。

通知使用持久待投递记录。入站短信、未读标记和投递任务同事务，提交后才确认硬件消息。
worker 独立投递，暂时失败从 15 秒指数退避至 5 分钟，永久失败保留安全原因。重启恢复
未完成任务；外部响应丢失允许重复投递，不承诺外部恰好一次。停用、取消订阅或删除
渠道／业务对象会取消相关未投递任务，不补发订阅前的事件。

增加 `vowifi.connected`、`vowifi.disconnected`、`cellular.connected`、
`cellular.disconnected`。首次确认在线通知，首次离线建立基线；每次确认变化立即通知，
不增加断线等待或合并短暂变化。未知和通信失败保留上次确认状态。蜂窝连接仅指本地／
漫游注册；5 秒只读探测无法保证捕捉两次采样之间已恢复的变化。

VoWiFi supervisor 提供携带实例、序号、观测时间和安全原因码的有序变更及带游标快照，
保留最近 1024 条。来源重启或游标过期重新校准并记录监测缺口，不猜测中间状态。
监测检查点、游标与通知任务原子提交；同对象、连接类型和渠道依次投递，其他对象独立。
连接消息只包含显示名称、连接类型、状态、时间和可确认的原因，不包含设备／SIM 身份、
手机号、私有网络或原始协议错误。新渠道默认订阅全部九类事件。

验证使用临时 SQLite、Simulator、协议 fixture 和浏览器集成；不包含部署或真实硬件操作。
