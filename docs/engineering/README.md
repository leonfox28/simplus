# 工程规范

这里保存项目专属的编码约定、边界合同和回归检查。修改代码前，按涉及的目录读取对应索引，再阅读相关专题和就近测试。

| 修改范围 | 规范入口 |
| --- | --- |
| `cmd/**`、`internal/**`、`api/**`、Go 测试、数据库 | [后端规范](backend/index.md) |
| `web/**`、路由、组件、查询缓存、浏览器测试 | [前端规范](frontend/index.md) |
| `Makefile`、构建与生成、容器、打包、硬件验证 | [基础设施规范](infra/index.md) |

产品范围、架构、公开证据和执行计划仍由[文档地图](../README.md)列出的文档负责。这里记录实现合同；代码、测试和规范不一致时，先核实当前实现及已接受的决策，再同步受影响的文档。

验证命令及其副作用见[本地开发工作流](../development.md)。先运行与改动直接相关的检查，再按风险扩大范围；硬件操作和公开资料始终遵守[安全与发布边界](../privacy-and-publication.md)。
